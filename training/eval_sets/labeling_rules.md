# 도구 호출 라벨링 규칙

Glople 여행 도우미 tool-calling 데이터(학습 데이터, 평가 세트 모두)의 정답을 붙일 때 따르는 규칙입니다.
[`scripts/build_tool_dataset.py`](../scripts/build_tool_dataset.py)가 이미 쓰고 있는 규칙을 명시적으로 적고,
생성기에 없던 사람 말투(슬랭, 고유어 숫자 등)를 어떻게 옮길지 정한 것입니다. 생성기를 고치거나 새 데이터를 쓸 때, 리뷰할 때 이 문서를 기준으로 맞춥니다.
여기서 "생성기"는 v2(`data/tool_calling_v2`를 만드는 현재 스크립트)입니다. 2026-10-17 밤샘 학습에 쓴 v1(`data/tool_calling`)이 이 문서와 어긋났던 곳은 4절(지역 없는 박물관류 요청)과 6절(되묻기 조사)에 따로 적었습니다.

`evaluate.py`의 exact match는 도구 이름과 인자를 **글자 단위로** 비교합니다(목록은 정렬, 앞뒤 공백 제거, 숫자 문자열만 정수로 바꿈).
그래서 같은 뜻이라도 표기가 하나로 정해져 있어야 하고, 아래 규칙이 그 표기를 정합니다.

## 1. 기록 형식

- `messages`는 정확히 세 개: system → user → assistant.
- system은 생성기의 `SYSTEM_PROMPT`를 한 글자도 바꾸지 않고 씁니다.
- 도구를 부를 때 assistant는 `"content": ""`와 `tool_calls`를 갖고, 각 호출은 `{"type": "function", "function": {"name", "arguments"}}`입니다.
  `arguments`는 `json.dumps(인자, ensure_ascii=False)`로 만든 **문자열**입니다.
- 되묻기·바로 답변일 때 assistant는 `content` 문장만 갖고 `tool_calls`가 없습니다.
- `tools`는 [`tools/glople_tools.json`](../tools/glople_tools.json) 전체를 그대로 넣습니다.
- `task`는 keywords / search / routes / detail / reviews / gloplers / weather / plan / parallel / clarify / direct 중 하나입니다.
  도구를 두 개 이상 부르면 `parallel`, 같은 도구를 두 번 불러도 `parallel`입니다.
- 평가 세트에는 `difficulty`(8절)와 `note`(왜 헷갈리는지 한 줄)를 더합니다.

## 2. 도구를 부를지 판단

| 상황 | 정답 |
| :-- | :-- |
| 여행 요청이고 도구의 필수 인자를 발화에서 모두 채울 수 있음 | 도구 호출 |
| 여행 요청인데 필수 인자 중 하나라도 발화에 없음 | 도구를 부르지 않고 되묻기 (6절) |
| 인사, 감사, 기능 질문 | 정해진 문장으로 바로 답변 (7절) |
| 여행과 관계없는 요청 (코드, 숙제, 주식·코인, 번역, 이메일·자소서 작성 등) | 정해진 거절 문장 (7절) |

- 인자를 지어내지 않습니다. 발화에 없는 지역·키워드·나이를 추측해서 채우면 오답입니다.
- 사용자가 명시적으로 거절한 요청("후기는 됐고", "날씨는 내가 볼게")은 부르지 않습니다.

## 3. 공통 표기 규칙

- **지역·장소명은 사용자가 쓴 표기 그대로** 씁니다. `제주도`를 `제주`로, `앙코르와트`를 `앙코르 와트`로 바꾸지 않습니다.
- 지역·장소 뒤에 붙은 것은 떼어냅니다: 조사(에, 에서, 이, 가, 은, 는, 랑 …), `쪽`, `쪽에`, `근처`.
  예: `삼척쪽에` → `삼척`, `할슈타트가` → `할슈타트`, `소쇄원이` → `소쇄원`.
- 해시태그는 `#`을 뗍니다: `#혼행` → `혼행`.
- 다음은 인자로 쓰지 않습니다 (방해 요소):
  - 사용자가 사는 곳 ("부산 사는 사람인데"), 이미 다녀온 곳 ("통영은 지난번에 갔으니까"), `말고`로 뺀 곳
  - 동행자 정보 ("와이프랑 갈 건데" → 성별은 본인 것)
  - 감사 인사 속 지역명 ("덕분에 교토 잘 다녀왔어요")
  - 장소명 안에 들어 있는 단어 ("세체니 온천"의 온천은 키워드가 아님)
  - 요청과 상관없는 시점 ("담주에 우포늪 가는데 뭐 하는 데야?"는 날씨 요청이 아님)
- 위 방해 요소는 **요청 대상이 아닐 때만** 뺍니다. 사는 곳·다녀온 곳이라도 그 자체가 요청 대상이면 인자로 씁니다.
  `칭다오 사는 한국분 중에 여행 도와주는 분`의 칭다오는 글로플러가 사는 곳이자 찾는 대상이므로 `hashtag: "칭다오"`입니다.
  `지난주 울진 다녀온 거 일정으로 남기고 싶어요`처럼 다녀온 곳이 요청 대상인지 방해 요소인지 두 갈래로 읽히는 발화는 평가 세트에 넣지 않습니다.

## 4. 도구별 규칙

### recommend_by_keywords (task: keywords)

지역(목적지)을 정하지 않고 취향만 말했을 때 씁니다. `박물관 추천해줘`, `축제 좀 골라 주세요`처럼 지역 없이 키워드인 장소 유형(박물관·미술관·축제·공연)만 말한 요청도 여기에 해당합니다 (아래 search_destinations 참고).

- `keywords`의 모든 값은 생성기 `KEYWORDS` 94개 목록에 **있는 표기 그대로**여야 합니다.
- 활용형은 원형 키워드로: `등산하고` → `등산`, `캠핑장` → `캠핑`, `서핑하러` → `서핑`.
- 여러 단어 키워드는 가장 길게 맞는 것 하나만: `고대 유적지` → `고대 유적` (`유적`을 따로 더하지 않음), `하이킹 코스`, `보트 투어`, `전통 마을` 등.
- 오타는 목록 표기로 고칩니다: `스노쿨링` → `스노클링`.
- 동의어는 **목록에서 뜻이 같은 항목이 하나뿐일 때만** 옮깁니다: `와이너리` → `와인`, `유네스코 세계유산` → `유네스코`.
  후보가 둘 이상이면(`바닷가` → 바다/해변/해안, `기차여행` → 기차/철도 여행) 정답이 하나로 정해지지 않으므로 평가 세트에 넣지 않습니다.
- `A 같은 B`처럼 A를 B의 예시로 든 말은 A를 따로 키워드로 넣을지 두 갈래로 읽힙니다
  (`유네스코 세계유산 같은 고대 유적지` → `["고대 유적"]`인지 `["유네스코", "고대 유적"]`인지). 평가 세트에는 넣지 않고,
  둘 다 취향이면 `유네스코 세계유산이나 고대 유적지`처럼 나열한 문장으로 씁니다. (`호수나 정원 같은 데`처럼 `같은` 뒤가 `데`·`곳`이면 앞의 말이 곧 취향이라 애매하지 않습니다.)
- 목록에 없는 말(조용한, 쇼핑, 단풍 …)은 버립니다. 버리고 나서 남는 키워드가 없으면 되묻기입니다.
- `맛집`이 "잘하는 곳"이라는 슬랭으로 쓰이면 음식이 아닙니다: `야경 맛집인 여행지` → `["야경"]`.
- 이 도구에는 `limit`이 없습니다. "세 군데만"처럼 개수를 말해도 인자에 넣지 않습니다.
- 순서는 상관없습니다 (평가 시 정렬). 같은 키워드를 두 번 넣지 않습니다.

### search_destinations (task: search)

특정 지역의 장소를 찾을 때 씁니다. 필수는 `region` 하나입니다.

- `region`: 3절 규칙대로 사용자가 쓴 지역명.
- `category`: 아래 표의 말이 있으면 해당 값. 생성기는 항상 카테고리 말을 넣으므로, 카테고리 말이 전혀 없는 검색("삼척 뭐 있어?")은 정답이 애매해 평가 세트에 넣지 않습니다.

| category | 사용자 표현 (생성기 train / 생성기 test / 이 세트에서 추가) |
| :-- | :-- |
| 관광지 | 가볼 만한 곳, 관광지, 명소, 볼거리 / 구경할 곳, 둘러볼 곳, 핫플 / 가볼만한곳 |
| 문화시설 | 박물관, 미술관, 전시관 / 기념관, 과학관, 갤러리 / - |
| 축제 | 축제, 행사, 공연 / 페스티벌, 박람회, 콘서트 / - |
| 레포츠 | 액티비티, 레포츠, 체험 활동 / 체험거리, 수상 레저 / - |
| 음식점 | 맛집, 식당, 먹을 곳 / 밥집, 음식점 / - |
| 숙박 | 숙소, 호텔, 잘 곳 / 게스트하우스, 펜션, 민박 / 게하, 묵을 데 |

v2 생성기는 여섯 카테고리 모두 test 전용 말을 씁니다. (v1 test는 구경할 곳·페스티벌·밥집·게스트하우스만 따로 있었고, 문화시설·레포츠는 train 말을 그대로 썼습니다.)

- 박물관·미술관·축제·공연은 키워드 목록에도 있습니다. **목적지 지역이 있으면 search의 category, 없으면 keywords**로 가릅니다.
  `피렌체 미술관 어디 가야 돼?` → search(문화시설), `박물관 미술관 돌아다니는 거 좋아해` → keywords.
- 지역을 되묻는 것(6절)은 지역 없이 **키워드가 아닌** 카테고리 말(맛집, 숙소, 액티비티, 관광지 …)만 있을 때입니다. `맛집 추천해줘` → 되묻기, `박물관 추천해줘` → keywords.
- 지역 없이 전시관·행사·페스티벌·갤러리처럼 키워드(박물관·미술관·축제·공연)와 뜻이 겹치는 카테고리 말만 쓴 발화는
  키워드 동의어 규칙(recommend_by_keywords)과 지역 되묻기 규칙이 부딪쳐 정답이 두 갈래입니다. 평가 세트에 넣지 않고,
  생성기는 지역 없는 요청에 문화시설·축제 카테고리 말을 아예 쓰지 않습니다 (지역 되묻기는 관광지·레포츠·음식점·숙박 말로만 만듦).
- `다음 달에 여행 가는데 박물관 알아보고 싶어요`처럼 여행이 이미 정해졌는데 목적지만 빠진 듯한 문장에 키워드인 장소 유형이 오면
  키워드 추천과 지역 되묻기 두 갈래로 읽히므로 넣지 않습니다. 같은 문장이라도 맛집·숙소처럼 키워드가 아닌 말이면 지역을 되묻습니다.
- v1 생성기는 지역 없는 `박물관 추천해줘`, `공연 찾아줘` 같은 요청을 지역 되묻기로 만들어(v1 train 6개) 이 규칙과 어긋났습니다. v2에서 keywords로 바꿨습니다.
- `query`: 카테고리 말 바로 앞에 붙은 조건(꾸밈말)을 **글자 그대로** 복사합니다. 조건이 없으면 넣지 않습니다.
  예: `아이랑 가기 좋은 숙소` → `"아이랑 가기 좋은"`, `흑돼지 밥집` → `"흑돼지"`, `사진 찍기 좋은 명소` → `"사진 찍기 좋은"`.
  카테고리 말의 일부인 `가볼 만한`·`가볼만한`, 개수 표현, 지역명은 query가 아닙니다.
- `limit`: 개수를 숫자나 한글 수사로 분명히 말했을 때만 정수로 넣습니다.
  `5개`, `4곳`, `세 곳` → 3, `두 군데` → 2, `다섯 개` → 5. `몇 개`, `두세 곳`, `여러 곳`처럼 정해지지 않은 말이면 넣지 않습니다.
- 카테고리가 둘이면(축제랑 숙소) `category`는 값 하나만 받으므로 search를 카테고리마다 따로 부릅니다 (task: parallel).

### recommend_similar_traveler_routes (task: routes)

`age`, `gender`, `mbti` 셋 다 필수입니다. 하나라도 없으면 되묻기입니다.

- `age`: 사용자가 말한 숫자를 정수로. `27살`, `34세요`, `38 남` → 27, 34, 38. 한글 수사도 숫자로: `스물다섯` → 25. 만 나이로 바꾸지 않습니다.
  `30대`, `96년생`처럼 정확한 숫자가 아닌 표현은 아직 규칙이 없어 평가 세트에 넣지 않았습니다. 새로 다룬다면 나이를 되묻는 쪽으로 통일하기를 권합니다.
- `gender`: 본인 성별만. `남자`·`남성`·`남` → `남성`, `여자`·`여성`·`여` → `여성`.
- `mbti`: 대문자 네 글자. `istj` → `ISTJ`. 한글 별칭은 글자로 바꿉니다:
  엔프피 ENFP, 인프피 INFP, 엔프제 ENFJ, 인프제 INFJ, 엔팁 ENTP, 인팁 INTP, 엔티제 ENTJ, 인티제 INTJ,
  엣프피 ESFP, 잇프피 ISFP, 엣프제 ESFJ, 잇프제 ISFJ, 엣팁 ESTP, 잇팁 ISTP, 엣티제 ESTJ, 잇티제 ISTJ.

### get_destination_detail (task: detail)

- `name`: 여행지 한 곳의 이름, 3절 규칙대로 조사만 뗀 표기.
- "어떤 곳이야", "정보", "소개", "사진이랑 위치" 같은 요청이 여기에 해당합니다 (도구 설명이 소개·사진·위치 조회).
- 지역과 장소가 같이 나오면 장소만: `영주 부석사 … 부석사가 어떤 덴지` → `"부석사"`.

### search_reviews (task: reviews)

- `query`: 후기를 찾을 장소명이나 지역명 하나. 붙어 있는 이유·맥락 문장은 넣지 않습니다.
- "후기", "리뷰"라는 말이 없어도 "다녀온 사람들 어땠대", "가본 사람들 반응", "갔다온 사람들 글"은 후기 요청입니다.

### search_gloplers (task: gloplers)

- `hashtag`: 지역명, 또는 관심사 해시태그(`#` 없이). `#혼행` → `혼행`, `캠핑 전문 글로플러` → `캠핑`.
- "글로플러"라는 말이 없어도 현지 가이드·현지 전문가·"현지 사는 분 중에 여행 도와주는 분"은 글로플러 요청입니다.
- 같은 문장에 장소·키워드처럼 보이는 말이 있어도("시엠립 앙코르 유적 투어 도와줄 현지 전문가") 요청이 글로플러면 지역명을 씁니다.

### get_weather (task: weather)

- `region`: 사용자가 말한 지역명. 날씨는 장소가 아니라 도시 단위로 묻는 경우가 많으니 장소와 도시가 같이 나오면 도시를 씁니다 (앙코르와트 + 시엠립 → `시엠립`).
- `when`: 아래 표대로 enum 값을 넣고, 시점을 말하지 않았으면 **생략**합니다 (도구가 오늘로 처리).

| when | 사용자 표현 |
| :-- | :-- |
| 오늘 | 오늘 |
| 내일 | 내일, 낼 |
| 이번 주말 | 이번 주말, 이번주말, 주말, 주말에 |
| 다음 주 | 다음 주, 다음주, 담주 |

- 표에 없는 시점(모레, 토요일, 다음 달, 지금)은 enum으로 옮기는 규칙이 아직 없어서 평가 세트에 넣지 않았습니다.
- "비 와?", "추울까?", "눈 온대?", "우산 챙겨야 해?"도 날씨 요청입니다.

### create_travel_plan (task: plan)

`region`, `days`, `places` 셋 다 필수입니다. 하나라도 없으면 되묻기입니다. 실제 저장 전에 앱이 확인 카드를 띄우므로 저장 의사를 따로 되묻지는 않습니다.

- `days`: 여행 일수(박이 아니라 일).

| 표현 | days |
| :-- | --: |
| N박 M일, N박M일 | M |
| 당일치기, 하루 | 1 |
| 이틀 | 2 |
| 사흘, 3일 | 3 |
| 나흘 | 4 |
| 일주일 | 7 |

- `places`: 사용자가 말한 장소명을 말한 순서대로, 표기 그대로. 장소명 안의 숫자(`동 루이스 1세 다리`)는 days와 무관합니다.
- `title`: 사용자가 일정 이름을 **직접 정했을 때만** 넣습니다. `'엄마랑 단둘이'로 이름 붙여서`, `'졸업 여행'이라는 이름으로` 등.
  `가족여행으로 … 가는데`처럼 여행 성격을 말한 것은 이름이 아니므로 넣지 않습니다.

## 5. 여러 도구 (task: parallel)

- 한 턴에 독립된 요청이 여러 개면 요청마다 한 번씩 부릅니다. 순서는 상관없습니다 (평가 시 정렬).
- 같은 도구를 인자만 바꿔 여러 번 부를 수 있습니다: 오늘이랑 이번 주말 날씨 → get_weather 두 번, 축제랑 숙소 → search 두 번.
- 같은 대상을 두 도구에 쓸 수 있습니다: `와인 테마 여행지 + 와인 해시태그 글로플러` → keywords `["와인"]` + gloplers `"와인"`.
- 한 요청이 다른 요청의 결과에 따라 달라지는 조건문("날씨 괜찮으면 맛집도")은 정답이 애매해 평가 세트에 넣지 않습니다.

## 6. 되묻기 (task: clarify)

필수 인자가 빠졌을 때는 도구를 부르지 않고 빠진 것만 짧게 묻습니다. `evaluate.py`는 도구를 부르지 않았는지만 채점하지만, 문장도 아래 틀로 맞춥니다.

| 빠진 것 | 답변 |
| :-- | :-- |
| 날씨의 지역 | 어느 지역 날씨를 알려드릴까요? |
| 검색의 지역 (키워드가 아닌 카테고리 말일 때만, 4절) | 어느 지역의 {카테고리 말}을/를 찾아드릴까요? (예: 어느 지역의 맛집을 찾아드릴까요?) |
| 루트의 나이·성별·MBTI 중 일부 | 비슷한 여행자를 찾으려면 {빠진 것}이/가 필요해요. 알려주시겠어요? |
| 일정의 지역·일수·장소 전부 | 어느 지역으로 며칠 동안, 어떤 장소를 넣어서 저장할까요? |
| 일정의 일수·장소 | 며칠 일정으로, 어떤 장소를 넣어서 저장할까요? |
| 일정의 장소만 | 어떤 장소를 넣어서 저장할까요? |
| 후기의 대상 ("거기 후기") | 어느 장소나 지역의 후기를 찾아드릴까요? |
| 키워드·지역 모두 ("아무거나 추천") | 어떤 여행을 좋아하시는지 알려주시겠어요? 바다, 야경, 사찰처럼 취향이나 가고 싶은 지역을 말씀해 주시면 찾아드릴게요. |

- 조사는 나열의 마지막 단어 받침에 맞춥니다: 나이**가**, 성별**이**, MBTI**가**(엠비티아이), 나이와 성별**이**, 성별**과** MBTI**가**, 나이, 성별, MBTI**가**.
  v1 생성기는 조사를 `가`로 고정해서 `나이와 성별가 필요해요`(v1 train 14개)를 만들었습니다. 채점에는 영향이 없었고, v2 생성기에서 고쳤습니다.
- v2 생성기는 이 표의 되묻기를 모두 만듭니다. v1은 날씨, 검색, 일정(전부 빠짐·일수와 장소 빠짐), 루트(셋 다·나이와 성별·MBTI만 빠짐)만 만들었습니다.
- 필수 인자가 아닌 것(search의 category·query·limit, weather의 when, plan의 title)이 없다고 되묻지 않습니다.
- 지역 없는 맛집 요청을 `recommend_by_keywords(["음식"])`로 우회하지 않습니다.

## 7. 바로 답변 (task: direct)

생성기의 고정 문장을 그대로 씁니다.

| 종류 | 예 | 답변 |
| :-- | :-- | :-- |
| 인사 | 안녕, ㅎㅇ, 반가워요 | `GREETING_ANSWER` |
| 감사 | 고마워, 땡큐, 덕분에 잘 다녀왔어 | `THANKS_ANSWER` |
| 기능 질문 | 뭐 할 수 있어?, 넌 누구야? | `ABILITY_ANSWER` |
| 여행과 무관 | 코드, 숙제, 주식·코인, 번역, 이메일·자소서, 로또 | `DECLINE_ANSWER` |

- 여행 맥락이 붙어 있어도 도구 범위 밖이면 거절입니다. 생성기가 번역 요청을 거절하므로 `도쿄 가서 써먹을 일본어 번역`도 거절입니다.
- 감사·인사 안에 지역명이 있어도 도구를 부르지 않습니다.

## 8. 난이도 기준 (평가 세트)

| 난이도 | 기준 |
| :-- | :-- |
| easy | 생성기 표현과 크게 다르지 않고 인자를 바로 뽑을 수 있음 |
| medium | 말투 변형(반말·오타·붙여쓰기·이모지·슬랭), 생성기에 없는 카테고리 표현, 조사 떼기, 간접 요청 중 하나 이상 |
| hard | 이 문서의 규칙을 알아야 맞힘: 동의어·오타 → 목록 표기, 한글 수사·고유어 일수, 방해 요소(사는 곳·간 곳·동행자·거절한 요청), 같은 도구 여러 번, 호출 3개 이상, 필수 인자 일부만 빠진 되묻기 |

hard 조건에 하나라도 걸리면 나머지가 쉬워 보여도 hard로 붙입니다.
예: `부다페스트 이틀 일정 저장`(고유어 일수), `ENTP 남자임`처럼 루트의 나이만 빠진 되묻기, `울진 가는데 일정으로 남겨두고 싶어요`처럼 지역은 있고 일수·장소만 빠진 되묻기.
날씨·검색처럼 필수 인자가 하나뿐인 도구에서 그 인자가 빠진 되묻기는 "일부만 빠진" 경우가 아닙니다.

hard 비율은 30% 안팎을 목표로 합니다.
